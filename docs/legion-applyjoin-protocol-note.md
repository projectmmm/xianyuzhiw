# 批量申请俱乐部协议记录

## 目标动作

目标功能是“申请加入普通俱乐部”，不是盐场/月赛/战区报名。

本次工程接入包含两步：

1. 通过 `legion_getinfobyid` 查询并确认目标俱乐部
2. 对未加入俱乐部的账号发起加入申请

## 当前实现采用的协议

- 查询俱乐部详情：`legion_getinfobyid`
  - 请求体：`{ legionId }`
  - 用途：查询目标俱乐部是否存在，并展示名称、头像、等级、成员数等信息

- 申请加入俱乐部：`legion_applyjoin`
  - 当前实现请求体：`{ legionId }`
  - 当前实现编码：复用 `xyzwWebSocket.js` 默认 BON 编码注册链路

## 命令来源

`legion_applyjoin` 的命令名来自仓库历史协议扩展线索，当前主线此前未接入该命令。

本次实现没有伪造额外字段，也没有从 UI 反推复杂结构，而是先采用现有命令名线索和统一编码链路接入，等待运行时验证。

## 已完成验证

- 已确认仓库现有代码可稳定读取 `legion_getinfobyid`
- 已确认页面和战区相关组件都在使用 `legion_getinfobyid` 拉取俱乐部详情
- 已将 `legion_applyjoin` 接入当前 websocket 命令注册与响应映射

## 待运行验证

以下内容仍需要在真实账号环境中确认：

1. `legion_applyjoin` 是否就是最终正确命令名
2. 请求体是否只需要 `legionId`
3. 响应命令是否为 `legion_applyjoinresp`
4. 服务端成功后是否立即返回可识别结果，或仅通过后续同步体现
5. 重复申请、申请已满、条件不足、已在俱乐部中时的准确错误码与错误文案

## 风险说明

如果真实运行结果表明：

- 命令名不是 `legion_applyjoin`
- 请求体还缺少字段
- 响应不是 `legion_applyjoinresp`
- 或该命令不走当前默认 BON 编码链路

则必须以真实抓包结果修正实现，不能把本文件视为“最终协议定稿”。
